# Architecture primers

Software architecture is the set of decisions about a system that are expensive to change later. They cover how it is split into parts, how those parts talk, where data lives, and which qualities (performance, security, availability, cost) win when they conflict. These primers introduce the vocabulary and the common styles.

- [Architecture decision records](architecture-decision-records.md): writing down why, not only what.
- [The C4 model](c4-model.md): diagrams at four levels of zoom.
- [Design principles](design-principles.md): SOLID, DRY, KISS and YAGNI.
- [Design patterns](design-patterns.md): the Gang of Four catalogue and how to use it.
- [Anti-patterns](anti-patterns.md): the shapes that code drifts into when nobody is looking.
- [Hexagonal architecture](hexagonal-architecture.md): ports, adapters and keeping the domain clean.
- [Domain-driven design](domain-driven-design.md): modelling the business and drawing boundaries.
- [Event-driven architecture](event-driven-architecture.md): components that react to things that happened.
- [Modular monolith or microservices](modular-monolith-vs-microservices.md): choosing how to deploy the parts.
- [Digital twins and device shadows](digital-twins-and-device-shadows.md): keeping a cloud copy of a device's state.

The [Handbook](../handbook/index.md) goes deeper into each of these, with the trade-offs and the review process. The [Glossary](../glossary/index.md) defines the terms.
